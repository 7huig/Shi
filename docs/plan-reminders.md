# 分类目标、静态提醒与热力图

[← 返回 README](../README.md)

## 为什么做

时间记录器最容易变成「记不全的自责工具」：空白块写着「未记录」，旁边还有「+ 补记」，用户一整天都在被提醒自己漏了多少。0.4.0 先把这些催促性文案拿掉，再用用户主动开启的分类计划，把「想记的事」轻轻放到首页。

所有提示都在应用内静态展示：不申请通知权限、不响铃、不弹系统通知，也不做与其他用户的比较。

## 入口

顶栏「⋮ → 目标与提醒」打开按分类的配置页。每个分类可以同时开启：

- **每日时长目标**：1–1440 分钟，父分类自动包含子分类的记录；
- **固定时间事项**：每天一个时间点 + 事项名，到点后在首页显示「到点了」；
- **间隔待办**：5–10080 分钟的间隔 + 待办名，完成后从点击那一刻重新计时；
- **热力图**：在時計页顶部展示该分类最近 24 周的每日用时。

四块配置相互独立。全部关闭时删除该分类的计划行，不留空记录。

## 首页静态提示

「今日提示」是时间轴上方的一排横向卡片，只在存在已配置计划时出现，按「先到期、后未到期」排序：

| 类型 | 展示 | 完成后 |
| --- | --- | --- |
| 每日目标 | 今日已记录 / 目标，进度条；未达成「还差 X」，达成「今日目标已达成」 | 记录自然推进，不需要额外操作 |
| 固定时间 | 今天 HH:mm + 事项名；到点前显示「今天」，到点后显示「到点了」；当天已有记录覆盖该时间则显示「已记录」 | 点卡片记一笔，记录覆盖固定时间后自动变为已记录 |
| 间隔待办 | 到期显示「该做了」，未到期显示「下次 HH:mm」；右侧「完成」按钮 | 写入 `lastCompletedAt = now`、`nextReminderAt = now + interval`，卡片与 Snackbar 立即刷新 |

点卡片本身会用该分类预填最近 30 分钟的记录，避免从提示跳到空白表单。

## 数据

Room v7 新增 `category_plan` 表，一个分类最多一行，外键 `ON DELETE CASCADE`：

```text
categoryId (PK) · heatmapEnabled · dailyGoalMinutes
fixedTimeMinuteOfDay (-1 = off) · fixedTimeLabel
intervalMinutes (0 = off) · intervalLabel
nextReminderAt · lastCompletedAt · updatedAt
```

保存规则：

- 间隔首次开启、修改间隔、或旧的 `nextReminderAt` 为空时，从当前时间重新计时；
- 只改事项名、目标或固定时间，不重置下一次提醒；
- 关闭间隔时清空下一次时间与完成历史；
- 删除分类时计划一起删除，不需要额外清理。

备份 schema 升到 3，`plans` 数组保存上述参数与下一次提醒时间；读取 schema 1 / 2 时计划为空。覆盖导入恢复计划，合并导入只给新分类补计划，不覆盖本机已有配置。

## 热力图

`CategoryHeatmapBuilder` 只为 `heatmapEnabled = true` 的分类生成数据，默认 168 天：

- 跨天事件按本地日历拆到前后两天；
- 父分类的每天累加整棵子树，与统计页「分类含子分类」口径一致；
- 颜色按该分类窗口内的每日最大值归一化，0 记录显示为空轨道色；
- 网格 7 行 × 24 列，置顶在统计页并居中，按分类列出，显示总时长与有记录天数。

## 边界

- 每个分类最多一条目标、一个固定时间事项、一条间隔待办；需要多个事项时可拆成子分类。
- 间隔待办只负责「提醒 + 重置计时」，不会自动生成时间记录；需要计时仍走正常记录流程。
- 提示只在应用打开时刷新，没有后台唤醒、WorkManager 或系统通知。
- 固定时间事项的「已记录」判定为当天有该分类（含子分类）的记录覆盖该时间点，不要求刚好从该点开始。
